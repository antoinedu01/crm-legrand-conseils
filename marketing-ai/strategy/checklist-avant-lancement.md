# Checklist avant lancement — à valider avant le 1er août 2026

> Brouillon marketing (LOT 1). Liste concrète des éléments à préparer et valider
> **avant** le démarrage des publications (Phase 2, dès le 16/08). Coordination :
> `marketing-director`. Contrôle : `compliance-reviewer`.
> **Aucune modification du site ni du CRM dans ce lot** : les points techniques
> ci-dessous sont **à réaliser par un humain** ; ici on ne fait que spécifier et
> vérifier. Cases à cocher lors de la validation humaine.

## Légende responsables
Humain = Antoine (dirigeant) · MD = marketing-director · CR = compliance-reviewer ·
CS = content-strategist · FUNNEL = conversion-funnel-designer · PA = performance-analyst ·
VIS = visual-flyer-director. *(Les agents produisent des brouillons/specs ; la mise
en ligne et les réglages techniques restent humains.)*

---

## 1. Profils sociaux
- [ ] Profils LinkedIn / Instagram / Facebook créés et complets (bio, coordonnées, zone Vaud/Genève). — Resp. : Humain
- [ ] Photo de profil et bannière cohérentes avec l'identité. — Resp. : Humain / VIS (brief)
- [ ] Lien vers le site présent et correct dans chaque profil. — Resp. : Humain
- [ ] Mention du statut « courtier indépendant et non lié » conforme au statut réel. — Resp. : Humain / CR — `Vérification humaine obligatoire`

## 2. Identité visuelle
- [ ] Logo, couleurs, typographies définis et disponibles. — Resp. : Humain / VIS
- [ ] Gabarits visuels (post, carrousel, story, reel) prêts. — Resp. : VIS (brief) / Humain
- [ ] Cohérence visuelle entre réseaux et site. — Resp. : VIS / MD

## 3. Liens du site
- [ ] Pages cibles identifiées (3e pilier, LAMal, prévoyance, ressources, contact). — Resp. : CS / Humain
- [ ] Tous les liens testés (pas de 404), en HTTPS. — Resp. : Humain
- [ ] Liens de CTA pointant vers la bonne page. — Resp. : FUNNEL (spec) / Humain

## 4. Formulaires
- [ ] Formulaire(s) de contact fonctionnel(s) et testé(s) de bout en bout. — Resp. : Humain / PA
- [ ] Champs limités au strict nécessaire (pas de sur-collecte). — Resp. : FUNNEL / CR
- [ ] **Aucune donnée médicale** demandée. — Resp. : CR — obligatoire
- [ ] Champ « source » du lead prévu/documenté. — Resp. : PA / Humain
- [ ] Message d'erreur et de succès clairs. — Resp. : Humain

## 5. Consentements
- [ ] Consentement nLPD **explicite, séparé, facultatif, non pré-coché**. — Resp. : CR / Humain — obligatoire
- [ ] Distinction claire entre « être recontacté pour ma demande » et « recevoir des informations marketing ». — Resp. : CR / FUNNEL
- [ ] Aucune inscription automatique à une newsletter lors d'un téléchargement. — Resp. : CR — obligatoire
- [ ] Version/date du consentement traçable. — Resp. : Humain

## 6. Pages de remerciement
- [ ] Page ou message de remerciement après soumission de formulaire. — Resp. : FUNNEL (spec) / Humain
- [ ] Page de confirmation de téléchargement (le cas échéant). — Resp. : FUNNEL / Humain
- [ ] Prochaine étape claire (« nous vous recontactons », délai indicatif). — Resp. : CS / Humain

## 7. Suivi UTM
- [ ] Convention UTM définie (source / medium / campaign) et documentée. — Resp. : PA
- [ ] Liens des réseaux et des CTA taggés. — Resp. : PA / Humain
- [ ] Test d'un lien taggé jusqu'à GA4. — Resp. : PA / Humain

## 8. Analytics
- [ ] GA4 opérationnel sur le site. — Resp. : Humain
- [ ] Événements clés vérifiés (vue formulaire, soumission `generer_lead`). — Resp. : Humain / PA
- [ ] Événement de conversion marqué comme « événement clé » dans GA4. — Resp. : Humain
- [ ] Tableau de suivi hebdomadaire prêt (modèle). — Resp. : PA

## 9. Appels à l'action
- [ ] CTA rédigés, progressifs et non intrusifs (cf. positionnement §8). — Resp. : CS / CR
- [ ] Cohérence CTA ↔ page de destination ↔ ressource. — Resp. : FUNNEL
- [ ] Aucune promesse interdite dans les CTA. — Resp. : CR — obligatoire

## 10. QR codes
- [ ] QR code(s) pour flyers/supports locaux générés et testés (redirection correcte, taggée UTM). — Resp. : VIS / Humain
- [ ] QR code menant à une page adaptée mobile. — Resp. : FUNNEL / Humain

## 11. Mentions
- [ ] Mentions légales et politique de confidentialité à jour et accessibles. — Resp. : Humain / CR — `Vérification humaine obligatoire`
- [ ] Mention du statut d'intermédiaire conforme. — Resp. : Humain / CR
- [ ] Coordonnées de contact correctes. — Resp. : Humain

## 12. Procédure de validation
- [ ] Circuit brouillon → conformité → validation humaine → diffusion **manuelle** formalisé. — Resp. : MD / CR
- [ ] Fiche `templates/content-validation-template.md` utilisée pour chaque contenu. — Resp. : CR
- [ ] Personne responsable de la validation finale identifiée. — Resp. : Humain

## 13. Responsable de chaque tâche
- [ ] Chaque tâche du plan 90 jours a un responsable identifié. — Resp. : MD
- [ ] Disponibilités et charge hebdomadaire réalistes validées. — Resp. : Humain / MD

## 14. Tests sur mobile
- [ ] Site, formulaires et pages de remerciement testés sur mobile (iOS/Android). — Resp. : Humain / PA
- [ ] Lisibilité des contenus sociaux sur mobile. — Resp. : SMM / VIS
- [ ] Temps de chargement acceptable. — Resp. : Humain

## 15. Protection des données
- [ ] Données collectées minimisées et hébergées de façon conforme (rappel : CRM sur infrastructure suisse). — Resp. : Humain / CR
- [ ] Aucune donnée personnelle réelle transmise à un outil d'IA externe. — Resp. : Tous — obligatoire
- [ ] Registre des traitements marketing à jour (si applicable). — Resp. : Humain / CR — `Vérification humaine obligatoire`

## 16. Procédure de traitement des leads entrants
- [ ] Délai de réponse cible défini (ex. sous 24–48 h ouvrées). — Resp. : Humain / MD
- [ ] Qui traite les leads et comment ils sont saisis dans le CRM. — Resp. : Humain
- [ ] Étapes de qualification définies (cf. KPI « leads qualifiés »). — Resp. : MD / Humain
- [ ] Aucune relance intrusive ; respect du canal et du consentement choisis. — Resp. : CR

---

## Verrou de lancement
> Le lancement (Phase 2) ne démarre que lorsque les points **obligatoires**
> (consentements, absence de données médicales, mentions légales, absence de
> promesses interdites, parcours site → CRM testé) sont **validés par un humain**.
> Ce document n'est ni un avis juridique, ni une validation FINMA.
